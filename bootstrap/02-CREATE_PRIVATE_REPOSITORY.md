# Step 2 — Create the Private Sovereign-State Repository

The repository is the person's durable state layer. It must be owned by the person and created as **private**.

## Explain it in functional terms

> We are creating a private place you own where a supported GPT can reliably return to your current state, decisions, projects, interests, and next steps—even after a conversation, device, or GPT changes.

The person does not need to understand Git internals.

The repository is one component of the person's human–AI operating configuration. It is not the person, the complete relationship, a dashboard, or an autonomous agent by itself.

## Creation steps

If the direct GitHub connection cannot create a repository, guide the person through GitHub's current repository-creation screen:

1. Choose a simple name, such as `<username>-sovereign-state`.
2. Select **Private** visibility.
3. Initialize it with a README.
4. Create the repository.

Do not create the person's private repository under the owner of this public bootstrap unless that is genuinely the person's own account and choice.

## Initial private structure

After direct GitHub access is connected and verified, adapt the files under [`templates/private-sovereign-state`](../templates/private-sovereign-state/) into the private repository:

- `RESUME_HERE.md`
- `START_HERE.md`
- `AGENTS.md`
- `state/BOOTSTRAP_STATE.md`
- `state/CURRENT_STATE.md`
- `trajectories/TRAJECTORY_TEMPLATE.md`
- `relationships/SHARED_REPRESENTATION_TEMPLATE.md`

The relationship template may remain unused indefinitely. Its presence does not authorize sharing or require a relationship channel.

Create only this minimum. Let later structure emerge from repeated real needs. Keep diagnostic, organizational, research, or other project work in its owning system and place only the source-safe personal relationship to that work here.
