# 第 4 步——从一到三件真实的事情开始

不做全面生活调查。只了解足以让持续帮助有用的信息。

## 从一件开始

只有本人愿意，而且增加内容确实会减轻负担，才加入第二或第三件。有用时可以包含：

1. 眼前重要的一件事；
2. 持续承担的责任或项目；
3. 一个兴趣、关系、愿望或可能性。

一到三件是节奏建议，不是配额、成熟度分数或对本人的定义。

## 每次了解一件

只使用有助于建立有用记录的问题：

- 是什么，为什么重要？
- 现在已确认什么，还有什么不确定？
- 下一步有意义的变化是什么，由谁负责？
- 应在何时或什么事件后再关注？是否需要多个独立的再次关注点？
- 各次关注如何实际发生：已验证提醒、外部日历、明确的人工查看或有意安静等待？
- 哪个系统或来源拥有原始事实？
- 哪些信息必须留在 Git 之外？
- 是否批准向特定他人分享？默认不分享。

对于刚出现的兴趣，目前可能只知道什么吸引了注意。为什么重要、下一步做什么、何时再关注，都可以尚未明确。这些问题用来帮助探索，不是开始探索前必须填完的表格。

每件事使用 [事项模板](../templates/private-sovereign-state/trajectories/TRAJECTORY_TEMPLATE.md) 单独保存。

不要把对话中所有已知事实导入仓库。把已有上下文解释成初始状态时，先提出最小有用表示，让本人确认、拒绝或纠正。本人直接请求记录明确更新时，已经授权这项有限内部工作，不再增加一次重复确认。推断的重要性仍标为解释，而非本人的既定决定。

## 证明记录能随现实变化

初始整理不是系统已经成熟。在提出更复杂的显示或连接前，至少成功处理一次后来发生的真实更新或纠正。它证明系统能跟随变化，而不只是保存初次问答。

当变化影响总体理解或下次继续位置时，更新 state/CURRENT_STATE.md、state/BOOTSTRAP_STATE.md 和 RESUME_HERE.md。
