# 第 3 步——让 GPT 直接连接 GitHub

普通设置使用受支持的 GitHub 插件或连接功能，不要求终端、本地仓库、VS Code、WSL 或 gh CLI。

产品界面会变化。检查本人当前 ChatGPT 环境能用的功能，按当前官方说明指导，不编造菜单名称或固定模型版本。

## 连接顺序

1. 确认当前网页、桌面或手机环境是否支持 GitHub 连接。
2. 需要设置时，指导本人进入当前可用的连接或插件界面。
3. 本人完成 GitHub 身份验证，并查看请求的权限。
4. GitHub 提供选择时，将访问范围限制到需要的账号和仓库。
5. 切换应用或登录前，保存不含秘密的继续位置。
6. 只有环境确实要求时才新开 GPT 对话，并从私有仓库继续，而非重做设置。

[官方产品说明：ChatGPT 与 Codex 插件](https://learn.chatgpt.com/docs/plugins)

## 用无害内容分别验证

在本人已授权设置的范围内：

1. 读取私有仓库的 README 或 RESUME_HERE.md。
2. 说明仓库名称，确认它确实私有，不重复个人内容。
3. 用中文版模板创建或适配 state/BOOTSTRAP_STATE.md，保留已有信息，不覆盖无关工作。
4. 重新读取写入结果，确认准确阶段。
5. 更新 RESUME_HERE.md，写明刚确认的结果及最小下一步。

登录成功、能读、能写是不同证据。只记录实际测试到的能力，不因为能读取就声称能写入。

## 如果连接失败

清楚说明缺少哪项能力；协助检查连接、仓库选择或权限；保存易懂的继续位置。能安全帮助的部分继续进行，必要时提供临时手动复制的简短记录。

不要为普通设置安装 gh CLI，除非本人明确选择了本流程之外的开发者方式。连接失败是技术条件，不是本人失败，也不是重做架构或公开信息的许可。
