# 第 2 步——使用本人拥有的私有仓库

仓库是本人的长期记录层，应由本人拥有，并设为 **Private（私有）**。

## 用实际用途解释

> 我们要使用一个由你拥有的私密位置，保存当前事情、决定、兴趣和下一步。这样即使更换对话、设备或 GPT，也能从已完成的地方继续。

本人不需要理解 Git 内部原理。仓库只是人机协作的一部分，不是本人、整个关系或独立智能体。

## 已经创建仓库

使用本人提供的准确仓库位置。先检查归属、私密性、现有内容及有效权限。不要仅凭名字认定所有权；不要再次创建或覆盖已有工作。如果仓库在助手账号下，不要把助手的技术控制描述成本人的所有权，先说明并解决实际归属。

## 需要创建时

若直接连接无法创建仓库，指导本人使用 GitHub 当前的创建界面：

1. 取简单名称，例如 `<username>-sovereign-state`。
2. 选择 **Private（私有）**。
3. 勾选创建 README。
4. 创建仓库。

不要默认创建在公开模板作者或设置助手的账号下，除非这确实是本人账号及本人的选择。

## 最初放哪些文件

连接和实际能力核实后，将 [中文版私有模板](../templates/private-sovereign-state/) 中的文件适配到私有仓库**根目录**：

- RESUME_HERE.md
- START_HERE.md
- AGENTS.md
- state/BOOTSTRAP_STATE.md
- state/CURRENT_STATE.md
- trajectories/TRAJECTORY_TEMPLATE.md
- relationships/SHARED_REPRESENTATION_TEMPLATE.md

保留路径和文件名，用中文填写内容。只写实际已确认的阶段；模板里的占位状态不是验证证据。保留已有 README 和其他工作，不把全部公开指南或他人状态复制进去。

关系模板可以一直不用，它不授权分享，也不要求建立渠道。以后随着真实需要增加结构。医疗、组织、研究等专门工作的原始状态留在所属系统，这里只保留适当且不泄密的个人关联。
