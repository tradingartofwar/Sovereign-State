# 隐私与安全

## 公开仓库

公开版只保存通用指南和虚构或去除识别信息的示例。不要写入参与者的个人状态。

## 私有仓库

个人仓库应设为私有，但私有 GitHub 也不是存放所有敏感材料的保险箱。只保存继续工作需要的最少状态，优先采用简要摘要和原始资料的位置引用，而不复制原件。

仓库是保存状态的工具，不是本人或完整人机关系的全部表示。

## 不写入 Git 的内容

- 密码、验证码、恢复码、通行密钥材料、访问令牌和私钥；
- 账号、保险、理赔或政府身份标识；
- 原始医疗、法律、财务、就业或教育记录；
- 私人通信或门户里的原始内容；
- 不必要的住址、电话号码或个人识别资料；
- 本人未授权保存的信息。

敏感原始材料应留在合适的密码管理器、加密系统、服务门户或其他受保护位置。Git 可保存不泄露敏感内容的引用及继续工作所需的简要说明。继续文件也不能含秘密。

## 对外分享的信息

遵循 [关系边界](RELATIONSHIP_BOUNDARIES.md)，只分享完成明确目的所需的最少内容。

- 一条消息、日期、请求或状态的分享，不开放整个仓库或日历。
- 私人状态、共有事实和关系信息分开。
- 检查实际权限，不把文件夹名称当成隐私隔离。
- 记录来源、时效、授权、到期及纠正或撤回路径。
- 被取代、过期、暂停或撤回的信息不再显示为当前。
- 新渠道先用无害内容测试。

## 权限

采用满足本人工作需要的最小仓库和连接权限。认证由本人在服务商界面完成，GPT 不索取聊天中的认证秘密。

添加协作者、公开仓库、连接新服务、建立关系渠道或扩大权限，需要明确授权。删除或破坏性历史修改需要明确确认及精确对象核实。设置完成后复查临时助手权限。

## 恢复

恢复不能只依赖一个设备、一段对话、一个 GPT 环境或一个助手。私有仓库保存不含秘密的继续信息，账号恢复资料留在 Git 和聊天之外。
