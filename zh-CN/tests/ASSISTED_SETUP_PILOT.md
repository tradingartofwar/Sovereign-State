# 有帮助者参与的设置试点

与真实参与者及必要时的可信帮助者一起使用本测试。不将参与者私人细节写入公共仓库。

获得辅助设置或已有上下文试点的证据后，先用[试点复核框架](../design/SEEDED_CONTAINER_PILOT_REVIEW.md)分析，再提议修改公共入门说明。

## 观察项目

### 立即有用与决定权

- GPT 是否在要求基础设施前帮助处理重要问题？
- 是否一次只问一个范围明确的问题，或给一个步骤？
- 最初一至三项是否有意义，而不是强加的？
- 本人能否区分自己的决定与 GPT 的建议？
- 本人能否说明私人仓库是状态工具，不是自身身份或完整代理？

### 访问与迁移

- 本人在哪里犹豫？
- 哪些词汇、画面或权限需要解释？
- 是否适用于本人实际设备？
- GPT 是否检查实际能力，而不是要求终端、本地检出或某一特定界面？
- 直接 GitHub 读取与写入是否分别成功？
- 中断、新对话、另一兼容设备或运行环境后能否继续？
- RESUME_HERE.md 是否准确、有用且不含秘密？

### 帮助者边界及退出

- 帮助者是否开始代替本人作出属于本人的决定？
- 是否获得凭据或超过需要的权限？
- 设置结束时是否复核临时权限？
- 本人能否理解、纠正并继续，无需帮助者代为操作？

### 可选能力

- 是否分别评估仪表盘、日历和关系通道？
- 是否只在减少负担时提供？
- 拒绝其中一种是否不影响其他能力？

如接受仪表盘：

- 本人能否识别来源和上次更新时间？
- 每个活跃事项是否显示，或有可理解的排除理由？
- 纠正是否先更新私人状态，再更新仪表盘？
- 已确认完成的事项是否退出当前关注，同时保留有意义的历史？
- 已接受的仪表盘是否保持地址、领域和布局稳定？

如连接日历：

- 是否准确保留约会、期限、计划、复核、例行事项和可能性的含义？
- 是否区分连接日历与授权分享日历？

如使用关系通道：

- 是否有真实接收者和用途？
- 本人是否审阅并批准确切的有限内容？
- 来源、时效、状态、复核、到期、纠正和撤回是否清楚？
- 无害的读取、写入、回复和实际权限测试是否通过？
- 是否能纠正或撤回信息而不暴露私人仓库？

## 只记录公共设计发现

试点后只将概括性、不能识别个人的发现加入复核或议题。个人状态留在其私人仓库或适当来源系统中。

区分直接观察、参与者报告、推断、设计启示和已确认纠正。不把推测的重要性当作已确立的个人状态。

## 通过标准

本人获得立即有用的帮助、安全恢复方式、至少一个有用的实际事项、需要时建立的本人所有的私人状态层、明确可迁移的恢复路径，并比开始时承受更少认知负担。

接受的展示层或关系能力应稳定、范围明确、可纠正、有用。本人能无需设置帮助者代为操作而继续使用。
