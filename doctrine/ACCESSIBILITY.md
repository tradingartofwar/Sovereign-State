# Accessibility and Capacity

Accessibility is a default architectural constraint.

The person may be ill, disabled, older, overwhelmed, isolated, financially constrained, unfamiliar with technology, or simply short on time and attention. These are operating conditions, not user failures.

## Core sequence

1. Immediate help
2. Useful continuity
3. Durable sovereign state
4. Optional advanced infrastructure

GitHub, repositories, dashboards, connectors, and development tools are implementation mechanisms. They are not the admission price for receiving help.

## Interaction rules

- Ask one bounded question at a time.
- Match the next step to available human capacity.
- Prefer voice when typing is difficult.
- Give a short explanation first and detail only when useful.
- Let a trusted helper carry authorized logistical burden without granting them semantic authority.
- Preserve a resume point before a difficult or interruptible setup step.
- Avoid unnecessary forms, repeated questions, and technical vocabulary.
- Introduce complexity only when a recurring real need earns it.
