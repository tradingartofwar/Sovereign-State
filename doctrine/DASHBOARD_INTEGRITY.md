# Dashboard Integrity

A dashboard is a correctable projection of living state. It helps the person see what matters now, but it does not become true merely because it is polished or visible.

## Stable identity

Once the person accepts a dashboard as their standing view:

- preserve its route, field names, and basic layout unless the person requests a change;
- treat a redesign as a proposed change, not a silent replacement;
- keep one clearly identified current dashboard rather than bouncing among competing displays;
- show the dashboard's source and an honest “as of” date.

A display failure, stale page, or interaction problem must never threaten the underlying state.

## Source-first update loop

When reality changes:

1. establish what changed and its evidence stage;
2. update the private repository or other named authoritative source;
3. regenerate or update the dashboard from that source;
4. reconcile what is visible, excluded, waiting, and closed;
5. verify that the accepted dashboard reflects the correction.

Do not use a manual dashboard-only edit as durable state. If an emergency display correction is made first, label it noncanonical and reconcile it back to the source promptly.

## Coverage and exclusions

Every active trajectory should either appear in the dashboard or have an explicit exclusion reason. Useful exclusion reasons include:

- completed or closed;
- superseded or duplicated;
- protected detail that belongs only in a source system;
- intentionally parked or outside the current attention field.

A coverage count or manifest can help detect silent omissions, but a count is not a substitute for checking meaning. Stale, reported, inferred, and unverified information must remain visibly distinguishable from established state.

## Movement, waiting, and completion

- A waiting item needs an owner or external party, the condition being awaited, and a return date or trigger.
- A reported intention is not proof of completion.
- When completion is established, retire the item from present attention while preserving its meaningful history and proof boundary.
- Do not let closed work remain visible merely because removing it is inconvenient.

## Human correction

The person must be able to correct the dashboard in ordinary language. A meaningful correction should update the authoritative state first, preserve why the earlier understanding changed, and then propagate to every affected projection.

The dashboard should reduce cognitive burden without acquiring authority over the person or the underlying state.
